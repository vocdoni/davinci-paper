In this section we describe the overall flow of the \davinci voting protocol. An election is structured into five main phases: election setup, encryption key generation, voting period, decryption key generation, and tally finalization. Each phase specifies the interactions between the organizer, \keywardens, voters, sequencers, and the smart contracts that coordinate the election. An overview of the complete process is shown in Figure~\ref{fig:protocol-flow}.

\subsubsection{Election setup}
\label{sec:vocdoni-protocol:setup}

In this phase, sequencers register and the organizer sets the election up.\\

\noi For each new election, the organizer performs the following steps:
\begin{enumerate}
	\item Prepare the census data \censusdata\ and generate the census Merkle tree $\censusTree$ with that data. 
	\item Compute the census commitment $\censusroot = \censusTree.\hlget{\MTRoot}()$.
	\item Prepare the voting form (ballot / set of questions), upload it to IPFS, compute commitment.
	\item Define the election details, including duration, options, and the ballot rules $\ballotmode$ (see Section~\ref{sec:ballot-protocol}).
	\item Compute a unique process identifier $\processid$, which is a 32-byte number derived from the organizer’s Ethereum address, nonce, and the chain ID.
	\item Set security parameters for the %forthcoming
	\ac{DKG} ceremony (e.g., timeout, minimum number of sequencers).
	\item Submit all this information in a transaction to the \hlget{\electionregistry} smart contract {\color{blue}(pay tx fees)}:
	\[ tx_{org} = (\censusroot, ballotCommitment, \ballotmode, electionMetadata, \processid, dkgParameters).\]
\end{enumerate}

\subsubsection{Encryption key generation}
\label{sec:vocdoni-protocol:keygen}

In this phase, \keywardens collectively generate the public encryption key.\\

\noi \Keywardens fetch the process parameters ($\processid$, $\ballotmode$, $\censusroot$) from the process management smart contract and participate in a \ac{DKG} protocol before the timeout set by the organizer expires. If the minimum number of contributions is reached, the public encryption key $\epk$ is derived and made available on-chain. This ensures that no single party controls the secret key, and that decryption later requires threshold participation {\color{blue}(give more details)}.\\

\subsubsection{Voting period}
\label{sec:vocdoni-protocol:votes}

In this phase, voters cast their ballots and send them to the sequencers, who collect and process them. \\

\noi \textbf{(a) Vote casting.} To cast a ballot, a voter does the following:

\begin{enumerate}
	\item Select a sequencer.  
	\item Retrieve their census membership proof $\censusproof$ to prove eligibility.  
	\item Fetch parameters $\epk$, $\ballotmode$, and $\processid$ from the \hlget{\electionregistry} smart contract.  
	\item Select their ballot choice $\ballot$ according to the rules of $\ballotmode$.  
	\item Sample fresh randomness $k \in \F$ and encrypt the ballot using $\epk$:  
		  \begin{equation}
		  \label{eq-ciphertext}
		  	\encryptedballot = \hlget{\Enc}_{\epk}(\ballot; k).
		  \end{equation}
	\item Use their Ethereum address $\address$ and the previous $k$ to compute a unique vote identifier:
		\begin{equation}
			\label{eq-voteid}
			\voteid = \hlget{\Multimimc}(\processid \conc \address \conc k).
		\end{equation}
	\item Use the \ballotcircuit from Section~\ref{sec:vocdoni-protocol:circuits:ballot} to generate a ZK-SNARK proof to prove that Eqs.~\labelcref{eq-ciphertext,eq-voteid} are correctly computed and that $\ballot$ satisfies the ballot protocol rules according to $\ballotmode$:
		\begin{align*}
		\voteproof = & \hlget{\PProve}(
			\hlget{\ballotcircuit},
			\witness = (\ballot, k), 
			\publicinputs = (\processid, \ballotmode,\\
			&\epk, \address, \weight, \encryptedballot, \voteid)).
		\end{align*}	
	\item Sign the vote identifier with their Ethereum secret key $\sk$ to authenticate the vote and ensure that was cast by a legitimate voter:  
		\[ \signature = \hlget{\SSign}_{\sk}(\voteid).\]
	\item Submit the package  
	\[\vote = [\processid, \voteid, \encryptedballot, \censusproof, \voteproof, \signature]\]  
	to the chosen sequencer.  
\end{enumerate}

\noi \textbf{(b) Vote batching.} Upon receiving votes, a sequencer does the following:

\begin{enumerate}
	\item Retrieve election identifier $\processid$, current state root $\stateroot$, and census root $\censusroot$ from the \hlget{\electionregistry} smart contract and the associated data from the Ethereum data blobs.  
	\item Upon receiving a vote
	\[\vote_i = [\processid, \voteid, \encryptedballot, \censusproof, \voteproof, \signature],\]
	extract the voter's public key $\pk_i = \hlget{\SPubKey}(\signature)$.
	\item For each $\vote_i$ received, use \verifiercircuit from Section~\ref{sec:vocdoni-protocol:circuits:verifier} to generate a proof 
	\begin{align*}
		\authenticationproof_i = & \hlget{\PProve}(\hlget{\verifiercircuit}, 
		\witness = (\ballotproof, \weight, \censusproof, \signature),\\
		& \publicinputs = (\processid, \ballotmode, \epk, \encryptedballot, \voteid, \\
		& \censusroot, \pk)).
	\end{align*}
	This proof ensures that the voter’s \voteproof, the \signature, and the \censusproof are all valid.
	\item Batch a set of $n$ proofs $\{\authenticationproof_i\}_{i = 1}^n$ and batch verify them together using \aggregationcircuit from Section~\ref{sec:vocdoni-protocol:circuits:aggregation}:
	\begin{align*}
		\aggregationproof = &\hlget{\PProve}(\hlget{\aggregationcircuit}, 
						\witness = (\{\authenticationproof_i\}_{i = 1}^n),\\
						&\publicinputs = (\encryptedballot, \{\voteid_i\}_{i = 1}^n),
						\{\pk_i\}_{i = 1}^n,
						\processid,
						\ballotmode,\\
						&
						\epk,
						\censusroot
						).
	\end{align*}
	This proof ensures that the public inputs corresponding to the global process parameters ($\processid$, $\ballotmode$, $\epk$, $\censusroot$) are correct and that all $\authenticationproof_i$ are valid.
	
	\item Prepare the state transition data that will be stored in an Ethereum blob: pack votes/results into a 4096-cell blob \blobdata. 
		\begin{itemize}
			\item Compute data commitment $\blobcom = \hlget{\CCommit}(\blobdata)$. 
			\item Derive evaluation point $\evalpoint = \hlget{\Poseidon}(\processid, oldRoot, \blobcom).$
			\item Prepare polynomial $P$ from $\blobdata$.
			\item Evaluate $y = P(\evalpoint)$.
			\item Generate opening proof $\openproof$ from $...$.
			\item The following step (circuit) will prove that $y = P(\evalpoint)$.
		\end{itemize}

	\item Finally, prove that all transitions are correct .... with circuit from Section~\ref{sec:vocdoni-protocol:circuits:state-transition}.
	consistency between data blobs and the on-chain state:
	
	\begin{align*}
		\stateproof = \hlget{\PProve}(\hlget{\statetransitioncircuit}, 
		\witness = (), \publicinputs = ()).	
	\end{align*}
	
	\item Verify each $\vote$ submission received by generating a state transition proof (see Section~\ref{sec:vocdoni-protocol:circuits:state-transition}), ensuring:
		\begin{itemize}
			\item correct accumulation of encrypted votes via ElGamal’s homomorphic properties,  
			\item eligibility of voters (via census Merkle proofs),  
			\item absence of double voting (or correct handling of overwrites via nullifiers),  
		\end{itemize}
	\item Submit the updated state root to the smart contract, while the full data are stored in Ethereum blobs.

\end{enumerate}

\subsubsection{Decryption key generation}
\label{sec:vocdoni-protocol:deckey-gen}

{\color{blue} After the voting period expires, $t$ out of $n$ sequencers publish their decryption shares of the election private key. Once the threshold is reached, the election secret key can be reconstructed (on-chain or off-chain), enabling the decryption of the aggregated tally.  
	
Rewards and penalties for sequencers are managed according to their correct participation: sequencers are rewarded proportionally to the number of votes sequenced, and may be slashed for failing to provide a valid decryption share (see Seciton~\ref{sec:token} for details on incentivation mechanisms.)}

The election is considered finalized once the decrypted tally is available on-chain. At this stage, both the election results and the complete integrity of the process are permanently recorded and publicly auditable.

{\color{blue} Note that, anyone can verify the correctness of the final results by checking the \ac{ZK-SNARK} state proofs and on-chain commitments. Moreover, the combination of the final state root, the decryption of the accumulators, and the publicly verifiable \ac{ZK-SNARK} proofs guarantees the integrity of the entire election.}
