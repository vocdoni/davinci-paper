In this section we describe the overall flow of the \davinci voting protocol. An election is structured into five main phases: election setup, encryption key generation, voting period, tally decryption, and election finalization. Each phase specifies the interactions between the organizer, \keywardens, voters, sequencers, and the smart contracts that coordinate the election. An overview of the complete process is shown in Fig.~\ref{fig:protocol-flow}.

\subsubsection{Election setup}
\label{sec:election-setup}

Before any election can begin, sequencers must register by staking \token tokens in the
{\color{blue}sequencer-registry} smart contract (see Section~\ref{sec:token}). This registration
is a one-time operation per sequencer and is independent of any particular election; only
registered sequencers are eligible to participate in the \ac{DKG} phase and to process votes.
%
For each new election, the organizer performs the following steps:

\begin{enumerate}
	
	\item Prepare the census data \censusdata\ and build the incremental Merkle tree
	$\censusTree$ from it. Publish the full tree to IPFS, and record the resulting URI as $\censusuri$.
	
	\item Compute the census commitment $\censusroot = \censusTree.\hlget{\MTRoot}()$.
	
	\item Define the election details, including duration, the census model $\censusorigin$
	(see Section~\ref{sec:vocdoni-protocol:census}), and the ballot rules $\ballotmode$
	(see Section~\ref{sec:ballot-protocol}). 
	
	\item Upload the election metadata (questions, options, description, etc.)\ to IPFS to obtain {\color{blue}electionMetadata}.
	
	\item Compute a unique process identifier $\processid$, which is a 32-byte number derived
	from the organizer's Ethereum address, nonce, and the chain ID.
	
	\item Initialize the state Merkle tree $\stateTree$ by inserting the election configuration
	parameters into the reserved configuration namespace (see Section~\ref{sec:vocdoni-protocol:state-tree}):
	$\processid$ at leaf $\mathtt{0x0}$, $\ballotmode$ at leaf $\mathtt{0x2}$,
	$\censusorigin$ at leaf $\mathtt{0x6}$, and zero-valued accumulators $\addaccumulator$ and
	$\substractaccumulator$ at leaves $\mathtt{0x4}$ and $\mathtt{0x5}$, respectively. {\color{blue}Compute the
	initial state root -- is this done by the SC?}
	\[
	\stateroot = \stateTree.\hlget{\MTRoot}().
	\]
	
	\item Set security parameters for the \ac{DKG} ceremony (e.g.\ timeout, minimum number
	of sequencers) {\color{blue}DKG}.
	
	\item Submit all this information in a transaction to the \hlget{\electionregistry} smart
	contract:
	\begin{align*}
		tx_{\mathit{org}} = \big(
		&\processid,\ \censusroot,\ \censusorigin,\ \censusuri, \\
		&\ballotmode,\ {\color{blue}electionMetadata},\ \stateroot,\ {\color{blue}dkgParameters}
		\big).
	\end{align*}
	
\end{enumerate}
%
Once this transaction is accepted, the election is publicly registered on-chain and the
\ac{DKG} phase can begin.

\subsubsection{Encryption key generation}
\label{sec:vocdoni-protocol:keygen}

In this phase, \keywardens collectively generate the public encryption key.\\

\noi \Keywardens fetch the process parameters ($\processid$, $\ballotmode$, $\censusroot$) from the \hlget{\electionregistry} smart contract and participate in a \ac{DKG} protocol before the timeout set by the organizer expires. If the minimum number of contributions is reached, the public encryption key $\epk$ is derived and made available on-chain. This ensures that no single party controls the secret key, and that decryption later requires threshold participation {\color{blue}(give more details)}.\\

\subsubsection{Voting period}
\label{sec:vocdoni-protocol:votes}

In this phase, voters cast their ballots and send them to the sequencers, who collect and process them. \\

\noi \textbf{(a) Vote casting.} To cast a ballot, a voter does the following: \textit{\color{blue}-- mention that the voter has a (sk, pk, address) as described in Section~\ref{}.}

\begin{enumerate}
	\item Select a sequencer.  
	\item Retrieve their census membership proof $\censusproof$ to prove eligibility.  
	\item Fetch parameters $\epk$, $\ballotmode$, and $\processid$ from the \hlget{\electionregistry} smart contract.  
	\item Select their ballot choice $\ballot$ following the rules of $\ballotmode$.  
	\item Sample fresh randomness $k \in \F$ and encrypt the ballot using $\epk$:  
		  \begin{equation}
		  \label{eq-ciphertext}
		  	\encryptedballot ={ }\hlget{\Enc}_{\epk}(\ballot; k).
		  \end{equation}
	\item Use their Ethereum address $\address$ and the previous $k$ to compute a unique vote identifier:
		\begin{equation}
			\label{eq-voteid}
			\voteid = N + \bigl(\hlget{\Poseidon}(\processid,\address,k) \bmod N\bigr),
		\end{equation}
	where $N$ is defined by the protocol as described in Section~\ref{sec:vocdoni-protocol:circuits:state-transition}.
	\item Use the \ballotcircuit from Section~\ref{sec:vocdoni-protocol:circuits:ballot} to generate a \ac{ZK-SNARK} proof to prove that Eqs.~\labelcref{eq-ciphertext,eq-voteid} are correctly computed and that $\ballot$ satisfies the ballot protocol rules according to $\ballotmode$:
		\begin{align*}
		\voteproof ={ } & \hlget{\PProve}(
			\hlget{\ballotcircuit},
			\witness = (\ballot, k), 
			\publicinputs = (\processid, \ballotmode,\\
			&\epk, \address, \weight, \encryptedballot, \voteid)).
		\end{align*}	
	\item Sign the vote identifier with their Ethereum secret key $\sk$ to authenticate the vote and ensure that was cast by a legitimate voter:  
		\[ \signature = \hlget{\SSign}_{\sk}(\voteid).\]
	\item Submit the package  
	\[\vote = [\processid, \voteid, \encryptedballot, \voteproof, \signature]\]  
	to the chosen sequencer.  
\end{enumerate}

	\item Upon receiving a vote

	\item For each $\vote_i$ received, use \verifiercircuit from Section~\ref{sec:vocdoni-protocol:circuits:verifier} to generate a proof 
	\begin{align*}
		\authenticationproof_i ={ } & \hlget{\PProve}(\hlget{\verifiercircuit}, 
		\witness = (\ballotproof, \pk, \signature),\\
		& \publicinputs = (\processid, \ballotmode, \epk, \encryptedballot, \voteid, \\
		& \address, \weight)).
	\end{align*}
	This proof ensures that the voter’s \voteproof and \signature are valid.
	\item Batch a set of $n$ proofs $\{\authenticationproof_i\}_{i = 1}^n$ and batch verify them together using \aggregationcircuit from Section~\ref{sec:vocdoni-protocol:circuits:aggregation}:
	\begin{align*}

						&
						\ballotmode,
						\epk

	\end{align*}
	This proof ensures that public inputs corresponding to the global process parameters ($\processid$, $\ballotmode$, $\epk$) are correct and that all $\authenticationproof_i$ are valid.

			\item Prepare polynomial $P$ from $\blobdata$.
			\item Evaluate $y = P(\evalpoint)$.

			\item The following step (circuit) will prove that $y = P(\evalpoint)$.

{\color{blue} Note that, anyone can verify the correctness of the final results by checking the \ac{ZK-SNARK} state proofs and on-chain commitments.
